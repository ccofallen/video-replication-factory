# 画质、单次时长与重新生成规则

按用户明确给出的画质数值记录 `job.json.profile.quality_level`，也适用于每窗 `profile_override`。画质值必须是正的有限JSON数值，不用宽、高、短边或像素总数推断档位。用户所称1.0为768p档；本地API只有宽高时，该字段是已核档位记录，不是凭空存在的服务器参数，仍保留当前API图的实际宽高设置。

| 明确画质数值 | 单次完整生成上限 |
| --- | --- |
| ≤1.0 | 15秒 |
| >1.0 | 10秒 |
| 未指定 | 10秒；需要15秒时先取得明确画质档位 |

仅已明确配置的RH `megapixels`／`resolution_selector.megapixels`可作为该数值的兼容记录；显式quality_level优先。不能仅改档位标签来绕过实际所用工作流的能力检查。不由720p、768p、原片尺寸或生成宽高反推画质值。

上限同时约束生成源区间和实际完整输出，context、preroll、时间放慢与补齐全部计入。先对齐本图真实帧网格再检查，不截掉真实动作或在生成后裁尾来规避单次上限。当前H3图24fps／17n+5：15秒内最多345帧（14.375秒），10秒内最多226帧（约9.417秒）。362帧约15.083秒、243帧约10.125秒，分别超过对应上限。其他工作流使用自身已核网格。

使用 `comfy_workflow.py h3-profile ... --quality-level 1.0` 显式建立低档profile（示例，不是新默认）；也可明确填写其他数值。生成器的参考视频加载帧数绑定当前完整generation_frames，不能仍固定240帧而截短长参考。已有run改变画质时先更新实际profile，再refresh-plan／prepare，重新审核受影响输入；档位进入input digest。已受理任务保留原ID恢复，不改写原请求或重投。

## 修改视频必须重新生成

`job.json.modification_method` 固定为 `regenerate`。人物、服装、动作、道具、字幕或局部瑕疵不合格时，定位受影响的完整生成窗，修改当前模型输入后重新生成整窗完整画面。身份参考和开头导引只作为模型条件，不直接覆盖候选或成片帧。

不贴人脸／服装／字幕贴片，不做局部蒙版、alpha叠加、局部抠图合成、换脸覆盖或复制源演员像素来修改视频。face_swap新提交、face_detail贴图入口与patched postprocessed delivery不用于当前制作。历史技术证明保留，不把旧方法当成当前许可。

保留无关的已通过窗口；重新生成的完整窗口按原owner与PTS组装，检查接点，保留原音轨。正常整窗剪接、尺寸适配、编码和原音轨封装不属于贴图，但不能借此新增人物或遮盖错误。新输出重新完成原图身份、动作、原速、原尺寸与接点验收，失败继续有针对性地重新生成。
